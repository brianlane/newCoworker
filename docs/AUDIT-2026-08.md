# Cursor-window audit, August 2026 (PRs #964 to #1038)

Tracked port of the 72-hour PR review that ran 2026-07-31 to 2026-08-05 over
the 75 PRs merged between 2026-07-27 16:00Z and 2026-07-30 23:36Z, essentially
all authored by Cursor, plus the verification pass run 2026-08-26 that checked
every claim against then-current main. The working tracker lived in a
gitignored file on one machine; this document is the durable record. Statuses
below are accurate as of **2026-08-26**, with every correction the tracker

Id scheme: `V` = VPS provisioning, `M` = billing and membership, `G` = tier
gating, `X` = cross-PR and repo rules, `TA`/`TB` = threads (Zapier publishing,
Zoom titles). These are cluster prefixes, not severity letters (unlike
[AUDIT-2026-07.md](AUDIT-2026-07.md), where M meant Medium).

## Executive summary

The window produced **37 findings, six of them P0**, concentrated in exactly
two clusters: VPS provisioning/billing (the sweep re-bought boxes it had just
bought, a failed deploy was reported as success and tore down the healthy old
box) and tier gating (the staff-request translator had no tier gate at all,
permanently-due Starter rows could starve every tenant's campaign sends). All
code fixes merged by 2026-08-05. Three findings were false positives or
wontfix on evidence, and those dispositions have held.

The 2026-08-26 verification pass re-checked all 37 against main at #1632:
every shipped fix is still present, none was silently reverted, and the
audit's own corrections were all accurate. It also found four defects the
audit missed (section "Verification pass" below), three of them in failure
classes the audit itself had named as its blind spots.

## Lessons, and whether each has a guard yet

1. **A mocked query builder cannot prove a table name, a column name, or a
   filter's effect.** Three findings in this window (V9, X1, the chat-leg
   table name) plus one after it (the `contact_overrides` erasure bug, see
   verification pass) are the same failure. The worker-integration harness
   (real local Supabase, `tests/worker-integration/*.itest.ts`) exists and is
   the correct tier. The routing rule now lives in
   `.cursor/rules/dev-workflow.mdc` and the README's workflow section
   ("A table, a column, or a filter needs a real database to prove").
2. **A defect inside a third-party SDK against a live service needs the real
   endpoint.** The password-change bug (#1166) was invisible to every unit
   test and was found by Zapier's reviewer. No standing auth-contract probe
   exists in `debug/`. Open item.
3. **Grep for the bare symbol, repo-wide, including dynamic `await import(`,
   before calling code dead.** The retraction above is the precedent. CI's
   `knip` runs with `--dependencies` (unused-export reporting disabled) and
   ignores `supabase/ vps/ cloudflare/ zapier/` wholesale, so it cannot catch
   this. Open item.
4. **Verify CORS with an `Origin` header.** Vercel's static serving replaces
   response headers only in the CORS case, which is exactly the case a plain
   curl does not exercise (and exactly what a DAST scanner does exercise).
   Applied during the CASA work; no repo guard needed beyond this note.

### New defects found (none were in the original audit)

1. **P1, live: end-user erasure aborts on a dropped table.**
   `src/lib/privacy/deletion.ts` deletes from `contact_overrides`, dropped
   2026-07-04 by the contacts unification (#277). The block was added
   2026-08-02 by #1128, four weeks AFTER the drop, and throws on the
   PostgREST 404, so any erasure request matching a contact row (either
   identifier axis; the block is gated on linked numbers, which an email-only
   request also populates) stops at table group 15 of 27 with 12 groups never
   run, and no retry can succeed. The run is not transactional, so the
   subject is left half-erased. The CI guard #1128 added scans migrations for
   `create table` with no `drop table` filter, so it kept believing the table
   exists. No coverage is actually lost by deleting the block: the data was
   folded into `contacts`, which the erasure already deletes.
   **Being fixed in the owner's fork** (with the dropped-table filter for the
   guard).
2. **P1, fired in production: V9's declined half.** See the V9 index row and
   the revised standing decision. Fixed by #1661.
3. **P1: a failed signup deploy was silent to everyone.** V17's fix
   suppressed the owner notice and left a comment claiming the stuck scan
   would tell ops. It cannot: the ops new-signup alert is gated on
   deploySucceeded, a signup job is marked succeeded on a normal return (no
   watchdog retry), and the stuck scan excludes error-status rows, which is
   what both failure rows carry. `deploy_failed`/`deploy_exception` sat in
   `STUCK_PHASE_HINTS` as unreachable entries. Fixed by #1664 (dedicated ops
   email; admin-only by decision).
4. **P2, latent: residency box schema drift.** `vps/data-api/schema.sql` is a
   2026-07-07 snapshot; 8 columns added centrally since are missing across 5
   moved tables, and the guard test covers only 3 of the 15
   RESIDENCY_MOVED_TABLES. One drifted column
   (`voice_call_transcripts.answering_machine_result`) is already in a routed
   projection, and `readMovedRows` throws with no fallback, so analytics call
   drill-downs go dark for the first tenant flipped to dual/vps mode. Latent
   because all tenants are `supabase` mode today; the flip is the deadline.

### Recorded open, with reasons

- **Clawback partial-refund idempotency (#1033 M-A/M-B).** The admin route
  double-deducts on a double submit with an explicit amount, and the
  auto-reload webhook feeds Stripe's CUMULATIVE amount_refunded into an
  incremental RPC on successive partial refunds. Both are the watermark
  problem #1063 documented: the RPCs are idempotent only for full voids.
  Fixing either properly needs the grant-row watermark; a partial fix
  (event previous_attributes deltas) would still double-apply on webhook
  redelivery. One design, three payoffs when built.
- **Contract-term nudge is once per subscription ROW (#1033 M-C).** Terms
  recur on the same row (auto-renew ON renews another term; the rollover
  CTA starts a new contract), but nothing ever clears
  contract_term_nudge_sent_at, so term 2+ never gets the notice. Needs a
  clear-on-renewal writer, not a query tweak.
- **Billing pause does not preserve pack grants (#973 F1's other half).**
  Grants ride invoice.paid, which a pause's voided invoices never fire, so
  a comped tenant's BUNDLED packs lapse at the period boundary; continuing
  those grants through a pause is a design task. (Auto-reload purchases
  deliberately continue during a pause, per the 2026-08-28 decision: they
  are the tenant's own top-up instruction, and blocking them degraded
  service.)
- **Priority support keeps billing through a pause (#973 F2).** It is a
  second Stripe subscription with no pause lever (admin offers pay_link |
  comp | cancel only). Needs its own pause or a panel warning; decide with
  the pause-semantics work above.
- **Paused tenants still count as revenue in margin/MRR (#973 F4).**
  Reporting-only; fold into the next margin pass.
- **Promo-aware nudges and stats (#983 F2/F3/F4).** The intro nudge quotes
  prices a forever-promo customer will never pay; promo stats record only
  the first invoice's discount; the order summary's renewal rows ignore a
  forever code. All display/reporting; the redemptions join exists when
  someone takes it.
- **Un-budgeted fail-but-charge recovery in change-plan/watchdog callers
  (#998 F4).** They do not pass deployBudgetStartedAtMs, so a recovery
  that eats the orphan wait can be killed by Vercel mid-post-provision.
  Thread the budget (the V7 fix pattern) through both callers.
- **Plan-mismatched never_renew boxes are claimable with 72h runway
  (#1008 F2).** Accepted-risk per #1661's decision; the daily
  migration-needed nag is the alarm.
- **CancelSheet is un-i18n'd wholesale**, so the pack-disclosure sentence
  is English-only there (the FAQ and order summary are bilingual; Terms is
  English-only by precedent). A full i18n pass on the sheet is its own
  task, not a one-sentence patch.
- **The deployed email worker was behind main** (last deploy 2026-08-05;
  #1483's postal-mime MAJOR bump merged Aug 18). DONE 2026-08-27: dry-run
  build clean, deployed (version 740495c8), and verified live: a probe
  mail to an unclaimed @newcoworker.com address hit the new version with
  outcome ok and zero exceptions under postal-mime 3.0 (wrangler tail
  capture; the fallback-forward handler completed).
